`frontend-qa` 서브에이전트를 **새 컨텍스트**로 띄워 검수시키고, 보고서를 그대로 전달한다.

작업 하나를 끝낼 때마다 부른다. 범위는 항상 **git 변경분**이며 저장소 전체를 검수하지 않는다. 범위 산정은 에이전트가 한다(커밋 전 변경 → 없으면 기준 브랜치 이후 커밋 → PR 번호를 줬으면 그 PR).

1. `$ARGUMENTS` 는 PR 번호 또는 기준 브랜치 이름만 받는다. 파일 경로는 받지 않는다.
2. Agent 도구로 `subagent_type: "frontend-qa"` 를 호출한다. 프롬프트는 아래 한 줄뿐이다. 이 대화에서 무엇을 왜 만들었는지, 어떤 파일을 고쳤는지는 넣지 않는다 — 검수원이 git 에서 직접 찾고, 작업자 사정을 모르는 것이 이 스킬의 목적이다.
   ```
   검수 대상: <"PR #<번호>" | "기준 브랜치 <이름>" | "현재 git 변경분">
   ```
3. 보고서가 오면 판정·소견 표를 **요약하지 말고 그대로** 사용자에게 보여 준다. 소견을 고치는 것은 사용자가 시킬 때만 한다.
